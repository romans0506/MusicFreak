# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

The MusicFreak **Expo app**. The Next.js web app lives one level up and is documented in `../CLAUDE.md` — the two are separate npm projects that share one Supabase project and one Spotify client_id.

## Commands

Run everything from `mobile/`, never from the repo root.

```bash
npm start          # expo start --go (Expo Go)
npm run ios        # open on an iOS device/simulator
npm run android
npm run lint       # expo lint
npx tsc --noEmit   # typecheck — the only automated check; there is no test suite
npx expo start -c  # clear the Metro cache (needed after EXPO_PUBLIC_* changes)
```

> **Never run `expo` from the repo root.** The root is the Next.js app; the Expo CLI treats it as an Expo project, installs `expo` into the root `package.json`, adds `"extends": "expo/tsconfig.base"` to the root `tsconfig.json`, and creates a root `.expo/`. With a version argument (`expo@57`) it also rewrites unrelated deps — it once downgraded `next` 16 → 9.3.3. Bundling then fails with `Unable to resolve "../../App"`, because the root has no `"main"`. Recovery: `git checkout -- package.json package-lock.json tsconfig.json && rm -rf .expo && npm install` in the root.

Typecheck from `mobile/`: the root `tsconfig.json` excludes `mobile`, so `npx tsc` at the root does **not** check this app.

## Architecture

**Expo SDK 54 + expo-router v6 (React 19, RN 0.81, new architecture).** File-based routes in `app/`. `"main"` is `expo-router/entry`.

**Route tree:**
- `app/_layout.tsx` — loads the display font, mounts `SessionProvider` + `NowPlayingProvider`, and gates routes with expo-router's `<Stack.Protected guard={...}>` (no manual redirects).
- `app/(tabs)/` — Games · Leaderboard · Artists · Stats · Profile.
- `app/artist/[id].tsx` — pushed over the tabs, registered in the root Stack.
- `app/login.tsx` — shown when there is no session.

Screens are headerless (`headerShown: false`) and handle safe-area insets themselves via `useSafeAreaInsets()`, because several leads with a full-bleed image that must run under the status bar.

**Typed routes are on** (`app.json` → `experiments.typedRoutes`). `.expo/types/router.d.ts` is generated by the dev server and is gitignored. After adding or deleting a route, `router.push` will fail to typecheck until you start the dev server once to regenerate it — a stale file also keeps declaring routes for files you deleted.

## Data access

Unlike the web app, there is **no API layer**. The device talks straight to Supabase with the anon key (`lib/supabase.ts`), and RLS does the scoping.

- Owner-scoped RPCs (`security invoker`): `get_play_counts`, `get_play_days`, `get_play_hours`, `get_listening_minutes`.
- Writes: `play_history`, via the scrobbler below.
- Cross-user RPC (`security definer`): `get_name_song_leaderboard`.
- Tables/views read directly: `profiles`, `leaderboard`, `scores`, `favorite_artists`, `favorite_songs`, plus the `profile-media` storage bucket.

The SQL for these lives only in the Supabase editor, not in the repo — see `../CLAUDE.md` for the schema.

`lib/stats.ts` is a **hand-copied port** of the web app's `src/lib/stats.ts` (`computeStreak`, `computeBadges`). There is no shared package between the two projects, so a change to one must be mirrored in the other or a streak will disagree across platforms.

## Spotify on the device

`lib/spotify.ts` reads `session.provider_token` **directly**. The web app forbids this and mints fresh tokens server-side, but minting needs the client secret, which cannot ship in an app.

**Consequence:** every Spotify-backed feature stops working roughly an hour after login and stays dead until the user signs in again. Each helper degrades to `null`/`[]` rather than throwing. When choosing what to build, prefer data paths with no such fuse — Supabase RPCs, and the keyless iTunes/lrclib APIs the web games use.

**What the device can and cannot call:**

| Endpoint | Works? |
|---|---|
| `/v1/me/...` (top artists/tracks, now-playing, recently-played) | yes, until the token ages out |
| `GET /v1/artists/{id}` (single) | yes — answers a user token |
| `/v1/search`, artist discography, batch `/v1/artists?ids=` | **no** — need the app token (client secret) |
| `GET /v1/artists/{id}/top-tracks` | **no** — deprecated, 403. Derive from `/me/top/tracks` across all three time ranges, filtered by artist |

Because catalog search is impossible here, the Artists screen filters the user's own top artists locally instead of searching Spotify, and the artist screen has no discography.

**One poller, app-wide.** `lib/now-playing.tsx` polls currently-playing every 30s (plus on foreground) and shares it through context. Both the mini-player and the profile panel consume it. Do not add a second poll — the `client_id` is rate-limited and a 429 on it also breaks OAuth login. `lib/scrobble.ts` rides this same tick for the same reason.

**Scrobbling — `lib/scrobble.ts`.** Every listening figure in the app (minutes, top artists/albums, streaks) is summed from rows *we* write into `play_history`; Spotify publishes no play counts. `ingestRecentPlays()` is the device-side twin of the web app's `<PlayScrobbler/>` + `/api/spotify/ingest-plays` — same `after=<last stored play>` cursor and same `(user_id, played_at)` dedup key, so both platforms write into one table without double-counting. **Keep the row shape in sync with `src/app/api/spotify/ingest-plays/route.ts`** (notably `duration_ms`, which is what minutes-listened sums). It self-throttles to 90s; pull-to-refresh on Stats and Profile calls it with `{ force: true }` before re-reading, so a pull visibly moves the numbers. Like everything else here it dies with the provider token ~1h after login — nothing is lost, since `recently-played` still returns the last 50 plays whenever a working token comes back, but a phone-only user who never signs back in will see listening time stall.

## Auth

Supabase Auth with Spotify OAuth, via `expo-auth-session` + `expo-web-browser` (`lib/auth.tsx`).

Supabase rejects both `exp://` schemes and raw-IP redirect hosts, so sign-in bounces through a public https page — `auth-bridge/native-auth.html`, published on the repo's `gh-pages` branch — which forwards the OAuth `?code=` on to the Expo Go deep link. Its origin comes from **`EXPO_PUBLIC_AUTH_BRIDGE`** in `mobile/.env.local`; `signIn()` throws without it.

Two things must stay in sync or sign-in breaks:
1. The bridge URL must be in Supabase → Authentication → URL Configuration → **Redirect URLs**. If it isn't, Supabase does not error — it silently discards `redirectTo` and sends the user to the project's Site URL (`localhost:3000`), which on a phone shows *"Safari cannot connect to the server"*. Diagnose by reading the address bar of the failed page.
2. `EXPO_PUBLIC_*` values are inlined at bundle time, so restart with `npx expo start -c` after changing them.

Env vars in `mobile/.env.local` (gitignored): `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_AUTH_BRIDGE`.

## Design system

Dark only. The palette mirrors the web tokens; crimson `#c81e33` is the single accent.

**Surfaces — `theme/surfaces.ts`.** Depth comes from tone, not blur: `background #121212` → `cardSurface #1c1c1e` (+1px hairline) → `raisedSurface #242427`. Shadows are tinted crimson, never neutral black. There is deliberately **no glassmorphism** — the old `BlurView` card was removed; `components/surface.tsx` replaced it. Don't reintroduce `expo-blur`.

**Type — `theme/type.ts`.** Manrope (loaded once in `app/_layout.tsx`) for headings and figures; the OS font for body text. Use the `typography.*` tokens rather than inline `fontSize`/`fontWeight`; tabular figures are baked into the number tokens.

**Icons — `components/ui/icon-symbol.tsx`.** SF Symbols on iOS, Material on Android/web. The `MAPPING` object is the app's entire icon vocabulary: TypeScript resolves the import to the non-platform file, so `name` is typed as `keyof typeof MAPPING` and an unmapped symbol will not compile. Add the pair when you need a new glyph. **Emoji are not used as iconography** anywhere — the only survivor is inside a bio placeholder, as example user content.

**Composition conventions:** each screen has a distinct shape rather than the same title-plus-card-stack (Stats leads with one 64pt figure over album art, Artists with a poster of your #1, Leaderboard with a podium). Loading states use `components/skeleton.tsx`, not bare spinners. Interactions fire `expo-haptics`. Looping animation is confined to the mini-player's level meter and the pull-to-refresh badge while a request is in flight; everything else animates on entry only, and reanimated hooks honour `useReducedMotion()`.

**Pull to refresh — `components/pull-refresh.tsx`.** `RefreshControl` is not used anywhere: its indicator is drawn by the platform and can't be branded. `<PullRefreshScroll refreshing onRefresh indicatorTop={insets.top + 8} …>` is a drop-in for `ScrollView` (it forwards every `ScrollViewProps`). Snapchat model: the page slides down and the mascot is hanging off its top edge by his fists, riding it down — fingers first, then the shades, then all of him. Behind the page is a `background`-coloured slab, so the gap reads as empty app rather than as a panel.

- The displacement is ours, not the scroll view's overscroll: a `Gesture.Pan` (rubber-banded, `1 - e^-t/300`) running simultaneously with the scroll view's own `Gesture.Native`, hence the `GestureHandlerRootView` in `app/_layout.tsx` that gesture-handler requires. **Trade-off:** the component forces `bounces={false}` / `overScrollMode="never"`, because native bounce would double the movement. Android has no bounce to begin with, and holding the page open during the request is only possible this way.
- Nothing animates layout: the slab is a fixed-height view parked above the screen and slid down by `translateY`, with the mascot as its `flex-end` child so his hands land on the page edge for free.
- **One animation owns the position.** `pull` is the single driver: the release either springs it to `rest` (slightly over-damped — settling must read as arriving, not bouncing) or times it back to 0. An earlier version ran a release spring *and* a separate parked-state spring behind a `Math.max`, and the two fighting is what made it judder on release. Don't reintroduce a second position value.
- `indicatorTop` is how far below the top his cap clears; the arm threshold and parked height derive from it plus the mascot size, so he's never left half-cropped while loading.
- The mascot (`components/mascot.tsx`) is react-native-svg, not an image asset — all-black, bandana under a backwards snapback, shades and mouth in `accent` (the only colour on him). His fingers deliberately run off the bottom of the viewBox so they read as wrapped over the page edge; keep that bottom flush if you reuse him.
